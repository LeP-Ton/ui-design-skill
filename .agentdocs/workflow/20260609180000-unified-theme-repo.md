# 统一主题仓库：从去中心化改为集中管理

## 背景与目标
- 去中心化方案（SKILL.md 内置索引 + 各主题独立仓库）存在发现问题：AI 无法自动发现新发布的主题
- 改为统一主题仓库：所有主题集中在一个 Git 仓库中管理
- AI 从统一仓库发现和安装主题，新主题通过 PR 贡献
- 一个场景可对应多个主题，用户可浏览选择

## 代码变更

### SKILL.md
核心理念：
```diff
-- **去中心化**：无中心市场，场景索引和仓库地址内置在 SKILL.md 中，规范靠 SKILL.md 定义，质量靠 AI 安装时校验
+- **统一主题仓库**：所有主题集中在一个 Git 仓库中管理，AI 从该仓库发现和安装主题，规范靠 SKILL.md 定义，质量靠 AI 安装时校验
```

```diff
-| 场景 | 关键词 | 默认 Theme | 仓库地址 |

-| `b-end` | ... | boss-theme | `https://github.com/example/boss-theme.git` |
+| 场景 | 关键词 | 默认 Theme |
+|------|--------|-----------|
+| `b-end` | ... | boss-theme |
```

Phase 2 主题加载：
```diff
-5. 若该场景的 theme 未安装，从场景表中的仓库地址 `git clone` 安装到 `themes/`

```

Phase 2.5 主题搜索与安装：
```diff
-- **搜索**：根据场景表中的仓库地址，列出可用主题

+- **安装**：从统一主题仓库复制需要的主题目录到本地 `themes/`
-- **查询**：先列本地已安装主题，再按场景表列出可安装主题
+- **查询**：先列本地已安装主题，再从统一主题仓库列出可安装主题
```

Theme 安装与卸载：
```diff

+- **安装**：从统一主题仓库复制主题目录到 `themes/`
```
